Развертывание нейросайта

Размещение сайта, созданного нейросетью, на сервере с помощью скрипта autodeploy.py

1. Копирование 2. Репозиторий 3. Запуск Результат
1
Копируем файлы сайта на сервер
Переносим готовый сайт на хостинг

Скопируйте все файлы сайта на сервер в папку, название которой совпадает с вашим доменом. Например, для сайта narkozav7.ru это будет папка /var/www/narkozav7.ru.

Важно: все файлы должны лежать прямо внутри этой папки, а не в дополнительной подпапке.

Команда для копирования
# Копируем файлы на сервер
scp -r ./site-files/* root@your-server:/var/www/narkozav7.ru/
✓

Если вы не знаете, как подключиться к серверу — используйте программу для SSH-доступа (например, PuTTY на Windows или Terminal на Mac) с данными, которые предоставил хостинг.

2
Создаём репозиторий на GitHub
Нужен, чтобы нейросеть могла обновлять сайт ВИДЕО

Репозиторий — это хранилище кода сайта на GitHub. Благодаря ему нейросеть сможет вносить изменения в сайт и автоматически обновлять его на сервере. Посмотрите видеоинструкцию, а затем выполните шаги ниже.

  1. Зайдите на github.com и нажмите кнопку New repository (новый репозиторий)
  2. В качестве имени укажите ваш домен, например be6st.ru
  3. Поставьте галочку Private (приватный), чтобы код сайта не был виден посторонним
  4. Создайте токен доступа — это специальный пароль для скрипта. Для этого: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
⚠

Сохраните токен сразу! После создания GitHub покажет его только один раз. Без токена скрипт не сможет подключиться к репозиторию. При создании токена убедитесь, что дали ему права на Contents, Webhooks и Administration.

ⓘ

Как понять, кто владелец репозитория: посмотрите на ссылку — например, https://github.com/Mmitekk/be2st.ru. Здесь Mmitekk — это владелец (логин), а be2st.ru — название репозитория. Эти данные понадобятся при запуске скрипта.

3
Запускаем скрипт развертывания
Скрипт сам сделает почти всё за вас

Подключитесь к серверу и запустите скрипт. Он задаст несколько вопросов, а всё остальное сделает автоматически: установит нужные программы, соберёт сайт, запустит его и настроит обновления.

Запуск
root@server:/var/www$ python3 autodeploy.py
  1. Название проекта — введите домен вашего сайта, например be6st.ru
  2. Путь к сайту — полный путь на сервере, например /var/www/be6st.ru
  3. Режим запуска — введите 1 (Standalone — это рекомендуемый режим)
  4. Домен и SSL — введите ваш домен. Если домен уже привязан к серверу и нужен безопасный протокол (HTTPS) — нажмите y. Если домен ещё не опубликован — нажмите n
  5. Логин владельца GitHub — логин из ссылки на репозиторий (например, Mmitekk)
  6. Название репозитория — имя репозитория из ссылки (например, be2st.ru)
  7. Приватный? — нажмите y
  8. Токен GitHub — вставьте токен, который вы создали на шаге 2
  9. Ждите — скрипт автоматически установит все зависимости, соберёт сайт, запустит его и настроит автоматические обновления. Это может занять несколько минут
✓

После завершения скрипта ваш сайт будет доступен по адресу домена. А при каждом обновлении кода в GitHub сайт будет автоматически обновляться на сервере.

1
Копируем сайт на сервер
MANUAL Подготовка файлов

Скопируйте файлы Next.js-проекта на сервер в директорию сайта. Путь должен соответствовать домену: /var/www/<domain>. Все файлы проекта (package.json, next.config.ts, prisma/ и т.д.) должны находиться непосредственно в корне директории, без вложенных подпапок.

SCP / Rsync
# SCP
scp -r ./site-files/* root@server:/var/www/be6st.ru/

# Rsync (рекомендуется для больших проектов)
rsync -avz --delete ./site-files/ root@server:/var/www/be6st.ru/
✓

Структура: package.json, next.config.ts и остальные файлы — прямо в корне /var/www/be6st.ru/. Скрипт ожидает именно такую структуру и автоматически определит конфигурацию standalone из next.config.*.

2
Создание репозитория GitHub
MANUAL Webhook-автодеплой ВИДЕО

Git-репозиторий на GitHub необходим для автоматического деплоя: webhook-сервер слушает push-события и запускает git pull && npm install && npm run build && pm2 restart. Создайте приватный репозиторий и Fine-grained PAT.

  1. Перейдите на github.com → New repository
  2. Имя репозитория — домен сайта (например, be6st.ru)
  3. Выберите Private
  4. Создайте Fine-grained personal access token: Settings → Developer settings → Personal access tokens → Fine-grained tokens. Права: Contents (R/W), Webhooks (R/W), Administration (R/W)
⚠

Токен показывается один раз. Скрипт использует его для git push и для проверки доступа к репозиторию через GitHub API (блок 12). Без прав repo на токене push и webhook не сработают.

ⓘ

Владелец и название: из URL https://github.com/Mmitekk/NarkoZav7 → владелец Mmitekk, репозиторий NarkoZav7. Эти значения вводятся в блоке 7 скрипта.

3
Запуск autodeploy.py
MANUAL INPUT 4 интерактивных блока из 15

SSH на сервер, запуск скрипта. Из 15 блоков только 4 требуют ручного ввода (блоки 1, 3, 4, 7), остальные — автоматические. Скрипт: определяет свободный порт, генерирует ecosystem.config.js для PM2, настраивает Nginx/Apache прокси, создаёт .env и .gitignore, выполняет npm install && next build && pm2 start, инициализирует Git, пушит в GitHub, запускает webhook-сервер.

Terminal
root@server:/var/www$ python3 autodeploy.py
  1. Название проекта — домен сайта (be6st.ru)
  2. Путь к проекту — /var/www/be6st.ru
  3. Режим запуска — [1] Standalone (node .next/standalone/server.js, требует output: "standalone" в next.config) или [3] автоопределение
  4. Домен и SSL — домен, SSL через Let's Encrypt (y/n)
  5. Логин владельца GitHub — из URL репозитория (Mmitekk)
  6. Название репозитория — из URL (be2st.ru)
  7. Приватный — [y]
  8. Fine-grained PAT — токен с правами Contents + Webhooks
  9. Ожидание — автоматические блоки: npm install, next build, pm2 start, git init/commit/push, webhook setup

Standalone vs Standard: Standalone — node .next/standalone/server.js, быстрее и меньше памяти, не требует node_modules для запуска. Требует output: "standalone" в next.config.ts/js. Что создаёт и настраивает скрипт

После успешного выполнения всех 15 блоков скрипт автоматически создаёт и настраивает:

  1. ecosystem.config.js — PM2-конфиг с autorestart: true, max_memory_restart: 500M
  2. Nginx/Apache vhost — proxy_pass на 127.0.0.1:{port}, alias для /_next/static/
  3. .env — PORT, DATABASE_URL (SQLite), NEXT_PUBLIC_SITE_URL, SECRET_KEY, ENABLE_SSL
  4. .gitignore — node_modules, .next, *.db, .env, logs, ключи
  5. Build — npm install --legacy-peer-deps && npm run build, проверка SWC-бинарника, fallback при OOM (2ГБ лимит)
  6. Git — init, remote с токеном в URL, initial commit + push
  7. webhook-server.js — HTTP-сервер на отдельном порту, слушает GitHub push-события и запускает git pull && npm install && npm run build && pm2 restart
✓

Автодеплой: при каждом push в репозиторий GitHub webhook автоматически подтянет изменения, пересоберёт проект и перезапустит PM2. Для нейросети обновление сайта — просто push в GitHub.
